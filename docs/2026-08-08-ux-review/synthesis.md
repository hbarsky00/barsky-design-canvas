# barskydesign.pro — UX Review Synthesis
**Date:** 2026-08-08
**Scope:** Homepage (`/`), case study detail (`/project/ring-rival`, spot check `/project/business-management`), blog index (`/blog`) and one rewritten post (`/blog/case-study-writing`). Desktop (1280×900) and mobile (375×812).
**Persona:** A founder or hiring manager evaluating whether to book a call with Hiram, arriving from a shared link or search result. Journey mapped: homepage → case study → (blog optional) → contact.
**Method note:** The dev preview's screenshot/scroll pipeline was unreliable for long, video-heavy scroll positions during this session (repeated blank captures, occasional pane hangs). Findings below below-the-fold on the homepage and inside the case-study image grid were confirmed via DOM/accessibility-tree inspection, computed styles, console logs, and source reading rather than a clean screenshot in every case — noted inline where relevant.

## Findings by severity
- **Blocker:** 0
- **Major:** 5 (4 fixed during this review, 1 reported only)
- **Minor:** 6
- **Polish:** 2

## Three highest-impact issues
1. **Image lightbox shipped with zero visible controls.** `ImageControls.tsx` (used by every maximizable case-study image, site-wide) unconditionally returned `null`. There was no visible close button and the zoom logic was fully wired but unreachable by any UI. Fixed: restored an accessible, labeled close button.
2. **Case-study templates are visually inconsistent.** Ring-Rival uses the new redesigned hero/layout; Business Management still renders the older "three laptops" template with different typography and button styling. A hiring manager clicking through 2-3 case studies back to back will notice the mismatch and read it as unfinished.
3. **Homepage header nav stays keyboard-focusable while invisible.** Before scrolling past the hero, the header is `opacity-0` (and off-canvas on mobile) but its 6 nav links remained in the tab order, so a keyboard user tabbing in from the address bar lands on invisible, unlabeled-looking focus stops. Fixed: header is now `inert` while hidden.

## Positive notes (not findings, for context)
- Contact form (`ContactForm.tsx`) has solid state coverage: zod validation with inline error messages, a disabled "Sending…" loading state, and distinct success/destructive-toast outcomes.
- Alt-text coverage across `<img>` usage was spot-checked broadly (grep across `src/`) and is consistently present.
- Case-study image/nav buttons (`NavigationButtons.tsx`) have correct `aria-label`s and hide themselves when there's only one image.
- Hero CTAs ("See My Work" / "Book a Call") are clear, low-friction, and above the fold on both viewports.
